通用约定

主键与编号

bigint identity 做主键，只在库内使用。对用户展示的一律是 order_no、reg_no 这类编号，二维码内容用随机的 ticket_code。

金额

*_cents bigint 加 currency char(3)。$21.93 存成 2193，不用浮点。柬埔寨同时有 USD 和 KHR 收款户。

枚举

用 text + CHECK，不用 PG enum。增减状态只需改约束，迁移成本低。

三语文案

jsonb：{"zh","en","km"}。赛事名、组别名、价格档名、商品名都按这个格式存。

个人信息

证件号存两列：id_no_enc 是 AES-GCM 密文，id_no_hash 是 HMAC，用于现场核验比对，不需要解密。个人信息长期保留，不做定时清理。

留痕

audit_logs、registration_changes、扫码流水、签署记录由触发器禁止 UPDATE/DELETE，只能追加。

报名订单状态机 reg_orders.status

和 Demo 的 10 分钟支付窗口不同，人工审核需要多一个"待审核"阶段。名额从下单起就锁住，审核期间一直保持。只有上传期或重传期超时才会释放名额，而且只释放一次。

  [*] --> PENDING_PAYMENT: 下单·预留名额与配额
  PENDING_PAYMENT --> PROOF_SUBMITTED: 上传截图
  PROOF_SUBMITTED --> PAID: 财务通过·RESERVED→CONSUMED
  PROOF_SUBMITTED --> PROOF_REJECTED: 驳回(原因码)
  PROOF_REJECTED --> PROOF_SUBMITTED: 重新上传
  PENDING_PAYMENT --> EXPIRED: 上传期超时·释放
  PROOF_REJECTED --> EXPIRED: 重传期超时·释放
  PENDING_PAYMENT --> CANCELLED: 付款前取消·释放
  EXPIRED --> PAID: 迟到到账恢复(重新占名额)
  PAID --> PARTIALLY_REFUNDED: 部分参赛人退款结算
  PARTIALLY_REFUNDED --> REFUNDED
  PAID --> REFUNDED

deadline_at 始终表示"当前阶段的截止时间"：下单后是上传期（默认 30 分钟），被驳回后是重传期（默认 24 小时），审核中为 NULL。时长配置在 system_settings。免费活动没有支付动作，不建订单，报名直接写入 free_signups。

关键事务

占名额：条件更新，不先查再改

一单里同组别的人合并成一次更新，影响行数为 0 就说明名额不够，整单回滚。CHECK (used_count + reserved_count <= capacity) 是最后一道兜底。

UPDATE event_categories
   SET reserved_count = reserved_count + $2
 WHERE id = $1
   AND used_count + reserved_count + $2 <= capacity
RETURNING capacity - used_count - reserved_count AS left;
-- price_rules 同理；任一返回 0 行 → ROLLBACK

超时释放：恰好一次

River 定时任务取出到期订单，跳过被其他进程锁住的行。以 reservation_state 从 RESERVED 改成 RELEASED 作为锚点，重复执行也不会释放第二次。

SELECT id FROM reg_orders
 WHERE status IN ('PENDING_PAYMENT','PROOF_REJECTED')
   AND deadline_at <= now()
 ORDER BY deadline_at LIMIT 100
   FOR UPDATE SKIP LOCKED;

UPDATE reg_orders
   SET status='EXPIRED', reservation_state='RELEASED',
       reservation_release_kind='ORDER_EXPIRED', expired_at=now()
 WHERE id=$1 AND reservation_state='RESERVED';
-- 影响 1 行才去扣减各组别 reserved_count

财务通过一份凭证

在一个事务里完成，任何一步失败就整体回滚：

-- 1 锁订单，确认仍是 PROOF_SUBMITTED
SELECT … FROM reg_orders WHERE id=$1 FOR UPDATE;
-- 2 凭证 → APPROVED（reviewed_by 必填）
-- 3 写 payment_receipts：同收款户同交易号唯一
-- 4 金额不符 → payment_exceptions(OVERPAID/UNDERPAID)
-- 5 组别/价格档 reserved → used，优惠码 CONSUMED
-- 6 订单 PAID、reservation CONSUMED、deadline NULL
-- 7 registrations PENDING → CONFIRMED
-- 8 audit_logs + River 任务：发凭证、分配号码布
COMMIT;

数据库守住的规则

这些规则即使 Go 代码写错也绕不过去。下表最后一列是在 postgres:16 容器里用测试数据实际触发的结果；对应审核报告里的 P0 问题，比如"退款可以超过已付款"，这里直接在库里拦住。

规则机制约束 / 触发器实测
组别名额不超卖（已确认 + 预留 ≤ 名额）CHECKevent_categories_no_oversell拦截
价格档配额、优惠码次数、周边库存不超卖CHECKprice_rules_no_oversell · merch_skus_no_oversell拦截
应付 = 挂牌价 − 优惠；已过期/已取消订单必须已释放名额CHECKreg_orders_check*拦截
识别分不超过 50 美分，应付 = 明细合计 − 识别分（报名、周边订单相同）CHECKident_offset_cents BETWEEN 0 AND 50拦截
付费赛事只能建订单，免费活动只能走免费报名和候补TRIGGER*_event_type拦截

不需要审核的跑友活动不能处于审核中或被驳回CHECKcommunity_activities_check*拦截

应用层负责的规则

下面这些规则跨行或跨表，写成数据库约束代价太高，由 Go 的领域模块负责，并配单元测试。

规则做法
价格档匹配组别允许的价格档 ∩ 身份可用 ∩ 配额有剩余，取最低价。结果写进 order_participants.price_rule_id，之后不再重算
优惠分摊按分分摊到每个参赛人，余数放在第一行；保证 Σpaid_cents = amount_cents
识别分分配在同一收款户、同一挂牌金额的待付款订单里，挑一个没被占用的 1–50 美分；全被占用时取 0，只靠交易号匹配
年龄资格按比赛当天的年龄和 min_age 比较
改拼写还是换人规范化姓名后，编辑距离 ≤ 2 或只是词序不同算改拼写；否则只能走转让，并生成新的 holder_id，证件核验需要重做
并发退款发起或结算前先 SELECT … FOR UPDATE 锁住参赛人行，避免两个财务同时结算绕过金额上限触发器
计数偏差每晚按参赛人和订单重新统计 used_count / reserved_count，和计数列对不上就写 ops_alerts
重复截图上传时按 sha256 精确匹配、按感知哈希找相似图，命中就标记 dup_file_hit，提示审核员
可见范围摄影师和现场人员的查询统一加赛事指派过滤；摄影师的接口不返回姓名、手机号、证件号

已确认的决定 2026-09-13

跑友活动是否审核，由赛事开关决定

每个赛事有 community_review_required 开关，打开就需要平台审核。不挂在赛事下的活动使用全局默认值 community.review_required_default。活动发布时把当时的规则写进 review_required，之后改开关不影响已发布的活动。

启用识别分，最多 50 美分

报名订单和周边订单都有 ident_offset_cents，范围 0–50，计入优惠，用户只会少付不会多付。交易号唯一仍是判断重复付款的硬约束。

免费活动不生成订单

没有支付动作，报名写入 free_signups，名额照样占用组别计数。数据库触发器保证付费赛事只能建订单、免费活动只能走免费报名。

一期不卖照片

没有照片订单相关的表，只保留免费领取、下载和"不是我"的记录。

个人信息长期保留

不做定时清理。证件号仍然加密存储，后台按角色脱敏展示，查看和导出都写入审计。
