Summary

一句话结论：骨架扎实，但三处安全缺口和「多套系统叠加」把它拖回了原型水平

业务语义层、RBAC 闸门、报名主链路的状态机都比一般原型认真得多；拖后腿的是后期叠加进来的东西：三套设计系统互相覆盖、两条底栏同时渲染、Telegram 集成只有空壳、UGC 与后台各有一处存储型 XSS、退款金额没有上限。

index.html · shared by desktop site and H5

官网 · H5 共用层

桌面官网与 H5 是同一份 index.html，这一节的问题两端同时存在：设计系统、路由、国际化、安全、性能、代码质量。

做得对的：47 个屏幕在 390px 下无一横向溢出（已实测）；无控制台错误；所有 img 有 alt、无重复 id、无 target=_blank 漏 rel；prefers-reduced-motion 双层处理正确；付费报名主链路 reg1→reg2→reg4→pay→done 与共享域衔接严谨，超时释放恰好一次；页面有 noindex。
Mobile web

H5 移动端专属

底部导航、响应式断点、表单与支付、移动网络下的加载、PWA 能力。

做得对的：KHQR 倒计时按订单 deadline 派生，休眠后恢复真实剩余；模拟支付按钮有「原型模拟」标注；「人工核查」正确地不确认到账；电话 / 邮箱输入类型正确；号码布输入用 inputmode=numeric；T 恤尺码用胶囊选择，触控友好。

assets/run-domain.js · D-092

共享业务域（横切四端）

它承诺「同一条业务规则只能有一处实现」，实际只把周边（merch）域和报名侧的预留 / 付款窗口 / 号码布 / 领物收进来了；报名退款状态机、订单聚合、赛事发布仍在后台直接改写 RD.state。130 个导出中 45 个两端都未使用。

做得对的：名额 / 配额写入边界与整单预留「全有或全无」；预留 exactly-once；周边侧退款 SETTLED 不加库存、退货只入库一次、LATE_ARRIVAL 不可拒绝；orderNo / PAID / EXPIRED / CANCELLED 均有幂等重入；Bib 号段 / 历史永不复用 / 赛内唯一校验完整。
Roadmap

修复路线（按依赖顺序）

Phase 0

止血

1–2 天 · 不动架构

  1. 补转义：UGC 四个渲染函数套 h()；后台 esc() 加 '，留痕 / 历史 detail 与 toast 全部转义。
  2. 金额上限：审批 ≤ 申请 ≤ 已付；结算 ≤ 批准；返还 / 补退 ≤ 差额；纠错单改用 parseSettleAmount。
  3. 路由：把 moments / rules / storydetail / publishmodal 加进 SCREENS，或删掉指向它们的 7 个入口。
  4. 重置清 PII：resetDemo 追加 RD.reset() 与 werun_* 键清理。
  5. 后台加 noindex；vercel 的 /admin 路由加访问保护。
  6. 字体：换成真正的分字重文件，preload 改为 400 + 700。
Phase 1

收口

1 周 · 对应 v7 视觉方案

  1. 设计系统：删除 2238 / 2663 / 2855 三个 :root 覆盖块，清 64 个死类、60 个重复定义，inline hex 回 token。
  2. 底栏二选一：保留 .mnav（已三语），删 .miniapp-bar；底栏 z-index 降到 modal / toast 之下；staff-mode 一并隐藏。
  3. 首页单 hero：移除 00 · SKY BANNER，去掉重复的 sports-pills。
  4. i18n：setLang 同步 document.documentElement.lang；先统一简 / 繁，再把 388 个未命中节点纳入字典。
  5. 过期弹窗复检：13 个 *ok 处理器在执行前重读状态。
  6. 脱敏统一：6 处绕过 pii() 的弹窗 / toast 收口。
Phase 2

补齐

2–3 周 · 需产品决策

  1. Telegram 实装：加载 SDK，ready/expand/theme/viewport/BackButton/MainButton/start_param；initData 校验留给服务端。
  2. 业务域收编：报名退款状态机、订单聚合、换号 / 作废、赛事发布迁入 run-domain.js；EVENT_MAP 改为数据。
  3. 免费活动进共享域：目前只写本地 S.regs，后台看不到。
  4. 后台平板：≤1024 收起侧栏、顶部控件换行、按钮 ≥ 44px、弹窗焦点管理与 Esc。
  5. 性能：拆分 527 KB 内联 JS，paintAll 只画当前屏并对 resize 去抖，图片补 width/height。
  6. PWA：manifest、theme-color、apple-touch-icon。
审核方法四路静态审查分别覆盖 index.html、admin.html、run-domain.js、MiniApp/H5 层，逐行读取并用脚本统计（选择器重复、i18n 键集、字体 MD5、对比度）；浏览器实测在 390 / 820 / 1280 / 1440 四种宽度下跑完 47 个用户端屏幕与 7 个后台角色，收集溢出、控制台错误、无障碍计数、网络请求与 localStorage。
